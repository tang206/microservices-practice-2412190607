# Week 02 项目选题

## 1. 项目名称
宠物医院管理系统

## 2. 要解决的实际问题和业务背景
国内宠物经济持续增长，家庭养宠数量不断上升，社区中小型宠物门诊的诊疗需求持续增加。但这类小型诊所普遍信息化水平偏低，长期依靠纸质登记、人工台账、Excel表格管理日常业务。人工操作容易引发预约时段冲突、手写病历丢失导致复诊缺少参考、药品库存数量不准、收费账目核对困难、门诊营收数据统计耗时费力等一系列问题，亟需一套轻量化数字化系统规范从预约、诊疗、开方到收费统计的完整业务流程。

## 3. 主要目标用户及其需求
1. **宠物主人**：注册登录后管理个人信息与多只宠物档案，浏览医生资料与值班时段，在线提交就诊预约；随时查看就医病历、复诊记录，查询历史缴费账单。
2. **兽医医生**：维护个人执业信息，查看每日预约清单；接诊时调取宠物档案和过往病历，辅助复诊判断，填写诊断内容，开具药品、检查项目处方。
3. **前台管理员**：审核预约申请，校验医生时段避免预约冲突；管理客户与宠物信息，配置医生可接诊时段；完成收费结算、药品库存管理，统计门诊订单量、营收等运营数据。

## 4. 选择该题目的原因
一方面我本身喜爱宠物，对宠物医疗场景比较感兴趣，做项目时更有动力深入打磨功能。另一方面该项目是真实落地的业务场景，三类角色职责边界清晰，包含预约冲突校验、处方管理、缴费与库存扣减事务、业务数据统计等典型开发场景，便于练习业务建模、角色权限、事务控制等基础开发能力。业务模块天然具备独立拆分的特性，适合先单体开发再改造为微服务，能够覆盖数据库设计、身份认证、消息队列、服务监控、容器部署等本学期课程学习内容。

## 5. 项目的初步边界，以及适合后续课程逐步演进的理由
项目范围限定为单门店宠物门诊业务，暂不实现住院护理、宠物线上商城、多分院连锁、远程视频问诊功能。各业务模块可拆分为用户档案、预约排班、病历处方、药品库存、收费统计等独立服务。可以先搭建单体SpringBoot应用快速实现完整业务闭环，后续逐步拆分为微服务，循序渐进完成数据库设计、权限认证、消息队列、事务控制、服务监控、容器部署等课程实验，业务复杂度适中，便于分阶段迭代开发。
